# Accessibility conventions (frontend)

The frontend is linted with [oxlint](https://oxc.rs/)'s `jsx-a11y` plugin
(enabled in [`frontend/.oxlintrc.json`](../frontend/.oxlintrc.json)), and the
tree is currently clean of `jsx-a11y` warnings. This page records the patterns
the components use so a new one keeps it that way, and why two rules are off.

Run the linter from `frontend/`:

```bash
npm run lint
```

## The three shared helpers

Everything below is built on [`frontend/src/lib/a11y.js`](../frontend/src/lib/a11y.js).

| Helper | Use for |
| --- | --- |
| `onActivateKey(handler)` | The keyboard twin of an `onClick` on a `<div>`/`<span>` that has to stay a `<div>`/`<span>`. Fires on Enter/Space, and ignores events that bubbled up from a nested control |
| `onBackdropClick(onClose)` | A `.modal-backdrop`'s `onClick` — closes only when the backdrop itself was the click target |
| `focusOnMount` | Callback ref that focuses a field when it mounts; replaces `autoFocus` |

## Pattern 1 — a clickable `<div>` / `<span>`

Prefer a real `<button>`. When the element cannot be one — it wraps other
buttons, or its layout depends on the tag — mark it up as a button instead:

```jsx
<div
  className="stage-row"
  role="button" tabIndex={0}
  onClick={select}
  onKeyDown={onActivateKey(select)}
>
```

Add `aria-expanded` on collapsible headers, `aria-pressed` on toggles, and an
`aria-label` when the element has no readable text of its own (image cards).

When the element is interactive only in some states, spread the interactive
props in as one group so the non-interactive state stays a plain container:

```jsx
<div
  className="json-tree-row"
  {...(isEmpty ? {} : { role: 'button', tabIndex: 0, onClick: toggle, onKeyDown: onActivateKey(toggle) })}
>
```

## Pattern 2 — modal backdrops

Every modal has a real close button, so closing by clicking the backdrop is a
pointer convenience: the backdrop is `role="presentation"` and the card inside
carries no click handler at all.

```jsx
<div className="modal-backdrop" role="presentation" onClick={onBackdropClick(onClose)}>
  <div className="modal-card">
    ...
  </div>
</div>
```

`onBackdropClick` replaced the old `onClick={(e) => e.stopPropagation()}` on the
card — same behaviour, one fewer handler on a static element.

The same `role="presentation"` marks other pointer-only affordances that have a
keyboard-reachable equivalent next to them: the mobile sidebar backdrop, the
Mureka track click-to-seek strip (its handler reads `clientX`), and containers
whose only job is to stop a click from reaching a clickable ancestor
(`.image-carousel-stars`).

## Pattern 3 — focus without `autoFocus`

```jsx
<input ref={focusOnMount} ... />
```

`focusOnMount` is declared once at module scope, so React runs it on mount only.
An inline `ref={(el) => el?.focus()}` would re-run on every render and keep
yanking focus back.

## Rules turned off, and why

| Rule | Why |
| --- | --- |
| `jsx-a11y/media-has-caption` | `<audio>`/`<video>` here play user-generated tracks and rendered clips. There are no caption tracks to point at, and an empty `<track>` would only add a dead entry to the player's subtitle menu |
| `jsx-a11y/prefer-tag-over-role` | It flags every `role="button"` from pattern 1 above. Most of those wrappers contain real `<button>`s, so a `<button>` tag is not a legal replacement, and converting the rest would mean adding button-reset CSS purely to satisfy a stylistic rule |

## Local exceptions

Two containers are focusable *and* listen for keys while deliberately staying
containers rather than controls, so they carry an
`eslint-disable-next-line jsx-a11y/no-noninteractive-tabindex, jsx-a11y/no-noninteractive-element-interactions`
with the reason written above it:

- [`EditorTimeline.jsx`](../frontend/src/components/workflow/EditorTimeline.jsx)'s
  `.tl-scroll` — the timeline's keyboard surface (arrows move between clips,
  Space/S/Delete act on them), `role="application"`.
- [`BlockCard.jsx`](../frontend/src/components/workflow/BlockCard.jsx)'s
  `.block-card` — takes focus so the 1-9 "insert special tag" shortcuts have
  somewhere to land, `role="group"`.
