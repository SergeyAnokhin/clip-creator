| [`providers/mureka_prompt_defaults.py`](../backend/app/providers/mureka_prompt_defaults.py) | The two Mureka base-prompt presets (`MUREKA_BASE_PROMPT_PRESETS`), same `{id, service, name, description, prompt}` shape as the Suno ones — merged with them by `routers/settings.py::get_suno_prompt_presets` |

| [`providers/scenes.py`](../backend/app/providers/scenes.py) | **Real seam (Google/OpenRouter/DeepSeek), mirrors `suno.py`.** `generate` builds a prompt from `scene_base_prompt_{scene_mode}` + active scene wishes + style/reference notes + raw lyric lines, asks for a `` ```json `` array of `scene_count` `{lyric_segment, scene_description, static_prompt, motion_prompt}` objects (`_parse_model_response`, tolerant — falls back to the deterministic chunked-lyrics stub on a malformed/wrong-length reply, `scene_description` left `''` in the stub); same stub fallback contract as `suno.generate` when no model/key. `scene_description` is a short Russian caption of what the shot shows (e.g. "женщина стоит в пол-оборота"), shown in `SceneTextCard.jsx`/`SceneCard.jsx`'s header so scenes can be scanned without reading the full English prompt |
| [`providers/images.py`](../backend/app/providers/images.py) | **Real seam.** `start_jobs`/`get_job`: one background `asyncio` task + in-memory job per requested image variant, dispatched by provider (Krea/Replicate/FAL job-polling, Google Imagen and OpenRouter single-call) to a real API call, writing the result under `app_data/projects/<slug>/images/` and persisting it onto the project on completion. OpenRouter's call reports its own exact cost (`usage.cost`), threaded through as `provider_cost` the same way `text_models.py`'s `_complete_openrouter` already does for text. `save_uploaded_image`/`download_user_image_url` back the scene-image-upload endpoint (`routers/generation.py`'s `upload_scene_image`): the former writes already-fetched bytes into the same `images/` dir + dict shape as a generated image (`model: 'upload'`); the latter is a **hardened** fetch for user-supplied URLs (unlike the unguarded `_download` used for trusted provider URLs) — only `http(s)` with a resolvable public host (`_is_public_host` rejects private/loopback/link-local targets, an SSRF guard), no redirects followed, `image/*` content-type required, response capped at `_MAX_UPLOAD_BYTES` (15MB) while streaming |
| [`providers/title_card.py`](../backend/app/providers/title_card.py) | **Real seam (Google Nano Banana `generateContent`, Krea's `google/nano-banana-pro` proxy).** `start_jobs`/`get_job`: same background-job/poll shape as `images.py` (own `_jobs` dict) but genuinely image-to-image — sends the stage's chosen reference images as `inline_data`/`style_images` alongside the text prompt; writes to `titlecard/` and persists onto `project.title_card.variants` (project-level, not scene-indexed). `_build_prompt` appends the quoted title/author text to `settings.title_card_base_prompt`. OpenRouter/Replicate/FAL deliberately not wired for multi-reference *generation* — see [architecture.md](architecture.md). `remove_background`/`_generate_background_remover` (Replicate's `851-labs/background-remover`, params from `settings.background_remover_params`) are the one place this module *does* call Replicate — a single-image edit, not a multi-reference generation, so the constraint above doesn't apply; goes through the **versioned** `/v1/predictions` endpoint via `_resolve_bg_remover_version` (cached module-level), not the shorthand `/v1/models/{owner}/{name}/predictions` route `images.py` uses — this community model 404s on the shorthand route (confirmed live, 2026-08); awaited directly by the route (no job/poll dance) and appends a new variant rather than replacing the source one |
| [`providers/title_card_prompt_defaults.py`](../backend/app/providers/title_card_prompt_defaults.py) | Seed text for `settings.title_card_base_prompt`, plus `TITLE_CARD_BASE_PROMPT_PRESETS` (3 built-in presets seeding `settings.title_card_base_prompt_presets`) |
| [`providers/translate.py`](../backend/app/providers/translate.py) | **Real seam.** `translate_text` — one-off prompt translation via the Google Cloud Translation API v2 (Basic, key-based), backing the Scenes/Images stage's "translate" button (`settings.api_keys.google_translate`, a separate GCP product/key from the Gemini one) |
| [`providers/url_parser.py`](../backend/app/providers/url_parser.py) | `httpx` + `BeautifulSoup` heuristic → `{author, title, raw_text}` |
| [`console_log.py`](../backend/app/console_log.py) | Colored, emoji-tagged dev-console lines for every real provider call (`log_request_start`, `log_result` — called from `usage._write` so it can never disagree with the ledger; `log_debug` prints the full, truncated (`_truncate`, 100-char string cap) request/response JSON a caller passes to `usage.record(..., debug=...)`, always — not just on failure); purely cosmetic, never raises |

See [usage-tracking.md](usage-tracking.md) |

### `hooks/` — where the state lives

Created in this order in `App.jsx`; each takes its dependencies as arguments,
so the wiring is explicit and there is no context/provider indirection.

| Hook | Owns |
| --- | --- |
| [`useToast`](../frontend/src/hooks/useToast.js) | The single transient message. Every other hook depends on `showToast` |
| [`useViewport`](../frontend/src/hooks/useViewport.js) | Breakpoint + workflow sidebar |
| [`useUsage`](../frontend/src/hooks/useUsage.js) | AI usage ledger and price catalog — created **before** `useSettings` (doesn't depend on it); see [usage-tracking.md](usage-tracking.md) |
| [`useSettings`](../frontend/src/hooks/useSettings.js) | Language (and therefore `L`), API keys (incl. `google_free` and `google_translate`), text/simple/image model favorites+default (× 2 tiers for image), request timeout, special tags, music + scene + title-card wish libraries (add with auto-title, edit title/text, delete, bump `use_count` on toggle-on — `removeWishSnippet`/`removeSceneWishSnippet`/`removeTitleCardWishSnippet` and `bumpWishUse`/`bumpSceneWishUse`/`bumpTitleCardWishUse`, all just a partial `PUT /api/settings` — the title-card one is only surfaced on `TitleCardStage`, not in `SettingsScreen.jsx`'s Wishes tab), scene base prompts (narrative/abstract), title-card base prompt + its user-managed save/load/delete presets (seeded with 3 built-ins), `backgroundRemoverParams` (local state, included in the bulk `saveSettings()` payload like `requestTimeoutSeconds` — no autosave), `logos` + `uploadLogo`/`deleteLogo` (dedicated endpoints, update state directly from the response, same pattern as the wish-library add/remove calls), `posterTemplates` + `savePosterTemplate`/`deletePosterTemplate` (Poster constructor's reusable logo+glass+text layouts — no file involved, so plain array CRUD via partial `PUT /api/settings`, same pattern as `titleCardBasePromptPresets`), `hideMotionPrompt` (autosaves immediately, shared by Scenes/Images stages), backup import (API keys / everything else, from an uploaded JSON file) |
| [`usePosterConstructor`](../frontend/src/hooks/usePosterConstructor.js) | Poster constructor's open/closed state (`openConstructor(poster?)`/`closeConstructor`), `savePoster` (uploads the flattened blob via `api.saveTitleCardPoster`, updates `project.title_card.posters` from the response, closes the modal), `deletePoster`, `selectMainPoster` (via `updateProject`, same debounced-autosave path as `useTitleCardStage`'s `selectMainVariant`). Kept separate from `useTitleCardStage.js` since posters composite existing artifacts rather than calling an AI model |
| [`useProjects`](../frontend/src/hooks/useProjects.js) | Project list, New-Workflow modal, open project, **and persistence** (`updateProject`, `flushPendingSave`) |
| [`useLyricsStage`](../frontend/src/hooks/useLyricsStage.js) | Block/line editing state and every block mutation |
| [`useSunoStage`](../frontend/src/hooks/useSunoStage.js) | Skill, `skill_prompt` ("Дополнения к промпту"), the AI-wish input + `addWish`/`toggleWish` (create/activate and toggle a project's `active_wish_ids`, bumps `use_count` via `onWishUsed` on toggle-on), generation, and `genModel` (which `text_models` favorite the next "Generate for Suno" call uses — seeded from `text_models.default`, session-only). The wish-cleanup model is **not** hook state; it's always `settings.simple_models.default`, read server-side |
| [`useScenesStage`](../frontend/src/hooks/useScenesStage.js) | Scene text: `sceneMode`/`sceneCount`, style description, the scene-wish input (`sceneWishText`, incl. mic dictation) + `addSceneWish`/`toggleSceneWish` (mirrors `useSunoStage`'s wish flow but against `active_scene_wish_ids`, bumps `use_count` via `onSceneWishUsed` on toggle-on), storyboard generation + debug/usage state, per-scene static/motion prompt edits; `sceneTextModel` seeded from `text_models.default`. | [`useImagesStage`](../frontend/src/hooks/useImagesStage.js) | Reference-image upload/remove, image variants, ratings, `imageModelTier` (`'simple'`\|`'main'`, picks which favorites list feeds `imageModel`) seeded from `image_models_simple.default`/`image_models.default`; `uploadSceneImageFile`/`uploadSceneImageUrl` (`POST .../images/upload`) add a user's own image to `scene.images` the same way a generated one is appended |
| [`useTitleCardStage`](../frontend/src/hooks/useTitleCardStage.js) | `project.title_card`: free-text `text_block` (lazily seeded to a quoted title/author template on first visit), up to 4 reference slots (auto-picked via `lib/titleCard.js`'s `pickTopReferenceImages` on project open, swappable/uploadable), the title-card wish input (`titleCardWishText`, incl. mic dictation) + `addTitleCardWish`/`toggleTitleCardWish` (mirrors `useScenesStage`'s wish flow but against `active_title_card_wish_ids`, bumps the wish's `use_count` via the `onTitleCardWishUsed` callback on toggle-on), `imageModelTier`/`imageModel`/`aspectRatio`/`variantCount` (mirrors `useImagesStage.js`), `generate` (flush pending save → `POST .../title-card/generate` → poll → append variants + `lastDebug`; `elapsedSeconds`/`titleCardError` mirror `useSunoStage.js`'s ticking-timer/persistent-error pattern), variant rating/select-main/delete/`removeBackground` (`POST .../remove-background`, tracked per-variant in `removingBgIds` since several can run at once). The base-prompt text/presets themselves live in `useSettings.js` (global, not per-project) |
| [`useVoice`](../frontend/src/hooks/useVoice.js) | Speech-to-text via the native Web Speech API (real recognition, no backend call — see [architecture.md](architecture.md#voice-input-speech-to-text)). Created **last** — it writes into the Suno refinement box, the Scenes wish box and the Title Card wish box (one `kind` string per target field, dispatched in `applyTranscript`). Also exports `useFieldVoice`, a project-independent variant `SettingsScreen.jsx` instantiates itself for wish-library dictation |

Stage hooks return `{ state, actions }`; `App.jsx` merges in the cross-cutting
bits (`specialTags` from settings, `startVoice` and the recording flags from
voice) when building each stage's prop bundle.
