## Backend — [`backend/app/`](../backend/app/)

| [`providers/image_models.py`](../backend/app/providers/image_models.py) | **Real seam (Google: `predict`/Imagen + `generateContent`-based "Nano Banana" ids; OpenRouter: `/models` filtered to `architecture.output_modalities` containing `image`), curated fallback (Replicate/FAL/Krea; DeepSeek stays empty).** `list_models` for the Settings image-model catalog, mirrors `text_models.py`'s shape (which excludes these same Google/OpenRouter image models from its own catalog); the catalog ids it returns are what `providers/images.py` actually dispatches on |
| [`providers/suno_prompt_defaults.py`](../backend/app/providers/suno_prompt_defaults.py) | Seed text for `settings.suno_base_prompt` / `suno_reference_examples`, plus the two Suno base-prompt presets (`SUNO_BASE_PROMPT_PRESETS`) — edited from Settings afterward, not from here |
| [`providers/mureka_prompt_defaults.py`](../backend/app/providers/mureka_prompt_defaults.py) | The two Mureka base-prompt presets (`MUREKA_BASE_PROMPT_PRESETS`), same `{id, service, name, description, prompt}` shape as the Suno ones — merged with them by `routers/settings.py::get_suno_prompt_presets`. Only presets for the Music-stage *text* generator — not the API client below |
| [`providers/mureka.py`](../backend/app/providers/mureka.py) | **Real seam (Mureka's official API).** `start_job`/`get_job`: one job per generate click (Mureka's own `n` returns several songs from one task, unlike `images.py`'s one-job-per-variant), `POST /v1/song/generate` then poll `GET /v1/song/query/{task_id}` every 3s (`_poll` also mirrors the intermediate `status` into `_jobs[job_id]['stage']`, exposed via the poll route so the frontend can show real progress); on success, downloads each `choices[].url` immediately (valid 30 days only) to `music/{track_id}.mp3` and appends one `MurekaTrack` per choice. `upload_reference_audio` wraps `POST /v1/files/upload` (`purpose=reference`) for the reference-audio-upload endpoint. `get_billing` wraps `GET /v1/account/billing` (balance pill). `start_extend_job`/`_run_extend_job`/`_submit_extend` mirror `start_job` almost exactly for `POST /v1/song/extend` ("Продлить" — same job/poll shape, request/response schemas confirmed against Mureka's own embedded OpenAPI spec since the public docs site doesn't render them). `stem_track` wraps `POST /v1/song/stem` ("Разделить на дорожки") — **synchronous**, no job/poll (the response already carries `{zip_url, expires_at, midi_zip_url}`); the local file is base64-encoded into a `data:audio/mpeg;base64,...` `url` field (10MB cap) instead of needing a hosted link, and the resulting zip is downloaded to disk immediately like everything else here. `trim_audio` shells out to `ffmpeg` (a **system** dependency, not pip — see README) to cut a reference-source upload down to the ≥30s window `ReferenceAudioTrimmer.jsx` picked, before it ever reaches `upload_reference_audio`. `_extract_error_message` parses Mureka's real `{"error": {"message": ...}}` error shape so callers see a clean message instead of a raw JSON blob (all raise sites in this file use it). No `pricing.py` catalog row for any of these — cost always resolves to `null`/unknown |
| [`providers/scenes_prompt_defaults.py`](../backend/app/providers/scenes_prompt_defaults.py) | Seed text for `settings.scene_base_prompt_narrative`/`scene_base_prompt_abstract` — see "The scene prompt" in [architecture.md](architecture.md) |
| [`providers/scenes.py`](../backend/app/providers/scenes.py) | **Real seam (Google/OpenRouter/DeepSeek), mirrors `suno.py`.** `generate` builds a prompt from `scene_base_prompt_{scene_mode}` + active scene wishes + style/reference notes + raw lyric lines, asks for a `` ```json `` array of `scene_count` `{lyric_segment, scene_description, static_prompt, motion_prompt}` objects (`_parse_model_response`, tolerant — falls back to the deterministic chunked-lyrics stub on a malformed/wrong-length reply, `scene_description` left `''` in the stub); same stub fallback contract as `suno.generate` when no model/key. `scene_description` is a short Russian caption of what the shot shows (e.g. "женщина стоит в пол-оборота"), shown in `SceneTextCard.jsx`/`SceneCard.jsx`'s header so scenes can be scanned without reading the full English prompt |
| [`providers/fal_client.py`](../backend/app/providers/fal_client.py) | `submit_poll_fetch` — the shared submit→poll→fetch skeleton for every FAL queue-based call (`POST {fal_base}/{model_id}` → poll `status_url` until `COMPLETED` → `GET response_url`), extracted 2026-08 after a 4th near-identical copy landed (`images.py`'s `_generate_fal`/`_call_outpaint_fal`, `title_card.py`'s `_generate_fal`/`_generate_background_remover_fal`). Only owns the 3 HTTP legs + timeout/failure/debug bookkeeping identical everywhere — request-body construction, result-shape extraction (`images[]` vs single `image`), NSFW checks, and downloading stay in each call site since those differ |
| [`providers/images.py`](../backend/app/providers/images.py) | **Real seam.** `start_jobs`/`get_job`: one background `asyncio` task + in-memory job per requested image variant, dispatched by provider (Krea/Replicate/FAL job-polling, Google Imagen and OpenRouter single-call) to a real API call, writing the result under `app_data/projects/<slug>/images/` and persisting it onto the project on completion. OpenRouter's call reports its own exact cost (`usage.cost`), threaded through as `provider_cost` the same way `text_models.py`'s `_complete_openrouter` already does for text. `save_uploaded_image`/`download_user_image_url` back the scene-image-upload endpoint (`routers/generation.py`'s `upload_scene_image`): the former writes already-fetched bytes into the same `images/` dir + dict shape as a generated image (`model: 'upload'`); the latter is a **hardened** fetch for user-supplied URLs (unlike the unguarded `_download` used for trusted provider URLs) — only `http(s)` with a resolvable public host (`_is_public_host` rejects private/loopback/link-local targets, an SSRF guard), no redirects followed, `image/*` content-type required, response capped at `_MAX_UPLOAD_BYTES` (15MB) while streaming. `crop_image` backs `ImageCropEditor.jsx`'s crop/outpaint editor (scene images only): computes how far the requested box overflows the source's bounds per side, does a free local PIL crop if none, else calls `_call_outpaint_fal`/`_outpaint_with_quality` (`fal-ai/flux-2-pro/outpaint`) for just the overflow before cropping down to the exact box — appends a new `Image` (`source_image_id` back-pointer), original untouched, same append-not-replace shape as `title_card.py`'s `remove_background` below. Capped at `_OUTPAINT_MAX_CANVAS_SIDE` (2560px/side, `OutpaintTooLargeError`); cost computed per-megapixel directly (no `pricing.py` catalog row, same `usage_out['cost']` bypass OpenRouter uses) |
| [`providers/video_models.py`](../backend/app/providers/video_models.py) | **Real seam (Google: filtered to `predictLongRunning`-capable/Veo models; OpenRouter: its own dedicated `GET /api/v1/videos/models` discovery endpoint), no curated fallback.** `list_models` for the Settings video-model catalog (`GET /api/settings/video-models/{provider}`) — only `google`/`google_free`/`openrouter` are valid providers, the only two confirmed to do image-to-video generation for this app; the catalog ids it returns are what `providers/video.py` actually dispatches on |
| [`providers/video.py`](../backend/app/providers/video.py) | **Real seam (Google Veo `predictLongRunning`, OpenRouter's Unified Video API).** `start_jobs`/`get_job`: same background-job/poll shape as `images.py` (own `_jobs` dict) but longer poll interval/timeout (6s/600s — video runs for minutes) and genuinely **image-to-video**: sends one scene image (`is_selected` or an explicit override) alongside the scene's `motion_prompt` + active video wishes (`build_prompt`, same "ВАЖНЫЕ ТРЕБОВАНИЯ ПОЛЬЗОВАТЕЛЯ" block convention as `scenes.py`). Google Veo is a long-running operation (`POST .../models/{id}:predictLongRunning` → poll `GET .../v1beta/{operation_name}` until `done` → download the result URI with the same `key` query param); duration snapped to Veo's `"4"`/`"6"`/`"8"` via `_nearest_google_duration`; no per-call cost, priced off the catalog's `per_second` rate. OpenRouter is `POST /api/v1/videos` (`frame_images`, `frame_type: 'first_frame'`) → poll `GET /api/v1/videos/{id}` → `unsigned_urls[0]`, with `usage.cost` threaded through as `provider_cost` same as its image API. Writes to `videos/scene_{n}_{shorthex}.mp4`, persists onto `project.scenes[n].videos` |
| [`providers/title_card.py`](../backend/app/providers/title_card.py) | **Real seam (Google Nano Banana `generateContent`, Krea's `google/nano-banana-pro` proxy).** `start_jobs`/`get_job`: same background-job/poll shape as `images.py` (own `_jobs` dict) but genuinely image-to-image — sends the stage's chosen reference images as `inline_data`/`style_images` alongside the text prompt; writes to `titlecard/` and persists onto `project.title_card.variants` (project-level, not scene-indexed). `_build_prompt` appends the quoted title/author text to `settings.title_card_base_prompt`. OpenRouter/Replicate/FAL deliberately not wired for multi-reference *generation* — see [architecture.md](architecture.md). `remove_background`/`_generate_background_remover` (Replicate's `851-labs/background-remover`, params from `settings.background_remover_params`) are the one place this module *does* call Replicate — a single-image edit, not a multi-reference generation, so the constraint above doesn't apply; goes through the **versioned** `/v1/predictions` endpoint via `_resolve_bg_remover_version` (cached module-level), not the shorthand `/v1/models/{owner}/{name}/predictions` route `images.py` uses — this community model 404s on the shorthand route (confirmed live, 2026-08); awaited directly by the route (no job/poll dance) and appends a new variant rather than replacing the source one |
| [`providers/title_card_prompt_defaults.py`](../backend/app/providers/title_card_prompt_defaults.py) | Seed text for `settings.title_card_base_prompt`, plus `TITLE_CARD_BASE_PROMPT_PRESETS` (3 built-in presets seeding `settings.title_card_base_prompt_presets`) |
| [`providers/translate.py`](../backend/app/providers/translate.py) | **Real seam.** `translate_text` — one-off prompt translation via the Google Cloud Translation API v2 (Basic, key-based), backing the Scenes/Images stage's "translate" button (`settings.api_keys.google_translate`, a separate GCP product/key from the Gemini one) |
| [`providers/url_parser.py`](../backend/app/providers/url_parser.py) | `httpx` + `BeautifulSoup` heuristic → `{author, title, raw_text}` |
| [`console_log.py`](../backend/app/console_log.py) | Colored, emoji-tagged dev-console lines for every real provider call (`log_request_start`, `log_result` — called from `usage._write` so it can never disagree with the ledger; `log_debug` prints the full, truncated (`_truncate`, 100-char string cap) request/response JSON a caller passes to `usage.record(..., debug=...)`, always — not just on failure); purely cosmetic, never raises |
| [`request_log.py`](../backend/app/request_log.py) | `RequestLogMiddleware` — one readable line per HTTP request (method emoji, path, status, duration, colored by outcome; no client IP, `HH:MM:SS` only), replacing uvicorn's default access log (disabled in `main.py`). See [usage-tracking.md](usage-tracking.md) |
| [`usage.py`](../backend/app/usage.py) | AI usage ledger — `record`/`query`/`summarize`/`today_total`, append-only `app_data/usage/YYYY-MM.jsonl`. See [usage-tracking.md](usage-tracking.md) |
| [`pricing.py`](../backend/app/pricing.py) | Price catalog + cost math (`BUILTIN_PRICING`, `get_price`, `compute_cost`, `estimate`, `catalog`) — pure, no I/O. Three row kinds: `text` (`input`/`output` per 1M tokens), `image` (`per_image`), `video` (`per_second`, e.g. Google Veo). `BUILTIN_PRICING` holds only a small set of cited, verified rows; everything else comes from a user override (manual or imported), see [usage-tracking.md](usage-tracking.md) |
| [`routers/usage.py`](../backend/app/routers/usage.py) | `GET /api/usage/records\|summary\|today`, `GET/PUT /api/usage/pricing` |

### `hooks/` — where the state lives

Created in this order in `App.jsx`; each takes its dependencies as arguments,
so the wiring is explicit and there is no context/provider indirection.
